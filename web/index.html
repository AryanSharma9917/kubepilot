Connect a development cluster

Start with a read-only identity for one namespace. Configure the API on the machine where it runs; never paste kubeconfigs, tokens, or credentials into this page.

  1. Ask your cluster administrator for get/list access to deployments, pods, events, and pod logs in your pilot namespace. Do not use a cluster-admin identity.
  2. Install the Python Kubernetes dependency: python -m pip install -e '.[dev,kubernetes]'.
  3. Set KUBEPILOT_K8S_MODE=kubeconfig and KUBEPILOT_KUBECONFIG to the local credential file. Set KUBEPILOT_ALLOWED_NAMESPACES to your pilot namespace.
  4. Optionally set KUBEPILOT_CLUSTER_DISPLAY_NAME to a recognizable label, then restart the API. Use in_cluster instead when deploying with a service account.
  5. Check a namespace below, then use Workloads to investigate an existing deployment by name.

Namespace-only credentials may not support Overview's cluster-wide list. A namespace allowlist is an application setting, not a replacement for Kubernetes RBAC. Use namespace-scoped Kubernetes credentials to enforce the boundary.

Getting started

Investigate a failure in five steps

KubePilot gathers Kubernetes evidence and troubleshooting guidance. You review and run any checks yourself.

  1. Choose a workload. Open Overview and select Investigate beside a workload needing attention.
  2. Review its signals. Read the observed problem, failure signals, pods, events, and logs.
  3. Choose your next check. Review explained commands and suggested checks. Commands are not executed by KubePilot.
  4. Ask with context. Select Ask about this workload, then Explain this failure. Clear context before asking about another workload.
  5. Share a snapshot. Return to Workloads and select Create incident report. Under Incidents, copy the status or download Markdown.

Three demo investigations

Use these scenarios when running the fixture demo. They are sample failures; refreshing does not repair them.

  • payments/checkout: inspect crashing containers, image pull failures, and missing configuration in logs.
  • platform/metrics-scraper: inspect readiness probe failures and deployment events.
  • notifications/email-worker: inspect pending pods and scheduling or resource constraints.

The Overview notice identifies the configured data source. An inspection service can also use fixtures; service mode does not prove a live cluster connection.

If something is unavailable

  • Workloads did not load: confirm the API is running and select Refresh. Developer activity is optional.
  • Deployment not found: check its namespace and name, or select an available workload.
  • No saved reports: create a report from an investigation first. Native in-memory reports reset when the API restarts.
  • Clipboard blocked: select and copy the text manually, or download the Markdown file.

Reports are snapshots and explanations are guidance. Verify the evidence before making a change.
